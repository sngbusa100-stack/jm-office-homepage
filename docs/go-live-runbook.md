# 개업일 순서표 (정명 행정사사무소 홈페이지·접수 연동)

개업 스위치를 켜는 순서다. 각 단계 뒤에 `npm run go-live:check`로 확인한다. 이 스크립트는 읽기 전용이라 아무것도 바꾸지 않는다. 설계: `docs/2026-10-19-go-live-check-plan.md`.

> 참고: 점검의 개업 전 문구 목록(`scripts/pre-open-phrases.mjs`)에는 '개업 전'·'개업 후'가 들어 있다. 앞으로 인허가 안내 등에 이 말을 정상 문구로 쓰면 잘못 걸릴 수 있으니, 그때는 목록을 좁힌다. 비자 사이트는 한국어 문구로만 검사한다.

> 원칙: **업무신고 수리 전에는 접수를 열지 않는다.** 행정사법 제10조 업무신고 전에 상담에 응하면 제36조②1의 처벌 대상이다. 점검 스크립트는 개업 전인데 접수 API가 열려 있으면 ❌로 알린다.

## 0. 개업 전 아무 때나
- `npm run go-live:check` — ❌ 항목이 "개업 전에 채울 것" 목록이다.
- 카카오 채널을 개설한다(개업 필수값, 2026-10-19 주인님 결정).

## 1. 사람이 끝낼 일
1. 행정사 업무신고 수리증을 받는다.
2. 대한행정사회에 가입한다(행정사법 제26조의2).
3. 사업자등록을 마친다.

## 2. 개업 커밋 (홈페이지 저장소)
1. `src/data/office.json`
   - `registrationNumber`(행정사 업무신고 확인 번호)
   - `businessNumber`(사업자등록번호)
   - `kakaoChannelUrl`
   - `openedOn`(개업일, YYYY-MM-DD)
   - `isOpen: true`
2. 개인정보처리방침: 개업하면 방침 안의 개업 전 문장이 바뀌므로 방침 변경이 된다.
   - `src/data/privacyPolicy.ts`의 `PRIVACY_EFFECTIVE_DATE`를 개업일로 바꾼다.
   - `api/_store.mjs`의 `CONSENT_VERSION`도 개업일로 바꾼다.
   - `PRIVACY_HISTORY`(변경 이력)에 "개업에 따른 상담 접수 개시"를 한 줄 추가한다.
3. 다음을 확인한다.
   - `npm run build`: verify-office가 필수값·개업일을 검사한다.
   - `npm run go-live:check`: 로컬 항목은 ✅여야 한다. 운영 항목(접수 API·운영 화면)은 아직 배포 전이라 ❌가 정상이다.
## 3. 접수 열기와 배포 (주인님 승인 뒤, 한 번에)
1. Vercel Production에 `CONSULT_OPEN=true`를 추가한다. 지금은 이 변수가 아예 없고, 없으면 닫힘으로 동작한다.
   - `npx --yes vercel env add CONSULT_OPEN production` → 값 `true`
   - 환경변수는 다음 배포부터 적용된다. 그래서 개업 커밋을 푸시하기 **직전**에 넣으면 배포 한 번으로 화면과 접수가 함께 열린다.
   - 순서를 거꾸로 하면 문제가 생긴다. 개업 커밋만 먼저 배포되면 폼은 켜지는데 API는 닫혀 있어, 그 사이 신청한 사람은 '전송 실패'를 보게 된다.
2. master 푸시(운영 배포)
3. `npm run go-live:check -- --strict` — 실패·건너뜀이 0이어야 한다.
   - 비자 사이트 문구 항목은 별도 과제(5개 언어 개업 후 문구)가 끝날 때까지 ❌로 남는다.
   - `/api/visa-handoff`도 같은 `CONSULT_OPEN`으로 열린다. 다만 빈 요청을 보내 시험하면 기록이 생길 수 있어 점검 스크립트는 이 API를 부르지 않는다.

## 4. 시험 접수 1건 왕복
1. 운영 상담 화면에서 시험 접수를 1건 넣는다(이름에 "시험" 표기).
2. 다음을 차례로 확인한다.
   - Telegram 접수 알림
   - 30분 안에 로컬 대기함 적재(회신 초안 포함)
   - 회신 완료 기록 → 홈페이지 '진행 중'
   - 문의 종결 → 홈페이지 '처리 완료'
3. /admin에서 시험 건을 파기한다.
