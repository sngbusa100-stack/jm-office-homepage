## 1. 왜 초점이 흐려졌나

10-16~19 작업(홈 개편, 문구 정정, 개인정보처리방침, 금지어 검사)은 모두 **접수 '입구'** 쪽이었다. 통합 마스터플랜(`D:\행정사\1-행정심판\docs\2026-07-19-통합-마스터플랜.md`)이 정한 최종 목표는 그 뒤의 흐름이다.

> 유입 → 셀프 진단 → 접수 → 로컬 연동 → 사건 → 자동 분석·초안 → 행정사 검토 → 답변 → 수임 → 문서 생성

이번에 코드를 직접 확인해 보니, 입구를 넓히는 동안 **접수 뒤의 고리가 두 군데 끊겨 있다**. 지금은 `CONSULT_OPEN=false`라 실제 접수가 없어 드러나지 않았을 뿐이다. 개업 전에 반드시 메워야 한다.

## 3. 끊긴 곳과 보완 방향 (우선순위 순)

### ① 로컬 대기함이 비자 답변을 버린다 — 데이터 유실 · 작업량 S~M
- **문제**
  - 로컬 `homepage_inquiries` 표에는 `diagnosis_json`, `utm_source`까지만 있다.
  - 홈페이지가 받는 `visaIntake`(체류 상태·기한·목적 등), `visaDiagnosis`(비자 사전진단), `attribution`, `consent`는 로컬로 넘어가지 않는다.
  - 수임 확정 뒤 클라우드 레코드를 파기하면 이 답변은 영구히 사라진다.
- **방향**
  - 로컬 표에 JSON 열 3~4개를 추가하고 대기함 화면에 표시한다.
  - 홈페이지 레코드(SCHEMA_VERSION 6)와 로컬 저장 필드를 대조하는 **연동 계약 테스트**를 양쪽에 둔다. 그래야 앞으로 필드가 늘어도 다시 끊기지 않는다.

### ② 로컬에서 끝낸 일이 홈페이지 접수함에 반영되지 않는다 — 이중 입력·파기 약속 · 작업량 M
- **문제**
  - 연동기는 가져간 사실(ACK)만 돌려보낸다.
  - 로컬에서 '종결(dismissed)'해도 홈페이지 접수함은 계속 '신규'로 남는다.
  - 방침에 적은 "처리 완료 후 120일 뒤 파기"는 주인님이 `/admin`에서 '완료'를 한 번 더 눌러야 지켜진다. 수임 사건만 클라우드 파기가 자동이다.
- **방향**
  - 로컬 종결·사건 전환을 연동 API로 홈페이지에 돌려보낸다(상태 동기화).
  - 오래 머문 미처리 건은 경고한다.
- **주인님 결정 필요(보고서 3절 질문 12)**
  - 로컬 '종결'을 홈페이지 '처리 완료'로 볼지
  - 끝내지 않은 건을 최대 며칠 두고 어떻게 할지

### ③ 운영 상태 일일 점검 알림 — 조용한 실패 방지 · 작업량 S
- **방향**: 매일 아침 Telegram으로 한 줄 요약을 보낸다.
  - 미처리 n건(그중 기한 우선 n건)
  - 연동기 마지막 성공 시각
  - 어젯밤 자동 파기 n건
  - 저장소 연결 상태
- **이유**: 사람이 대시보드를 열지 않아도 이상이 드러나게 하는 가장 값싼 자동화다. 개업 직후 가장 쓸모가 크다.

### ④ 회신 초안을 접수 답변으로 자동 작성 — 자동화 · 작업량 M
- **방향**
  - 분야 템플릿에 접수 때 받은 답을 채워 넣는다. 예: 체류자격·만료일·받은 문서·마감일.
  - 이미 받은 질문은 다시 묻지 않고, 기한 우선 건은 첫 줄에 기한을 둔다(GP-05).
- **원칙**: 자동 발송은 하지 않는다(2026-07-11 결정). 초안 → 행정사 검토 → 발송 순서를 지킨다.

### ⑤ 분야별 처리 경로 — 6개 분야 전부 · 작업량 M
- **현재**: 비자·인허가·보훈·토지는 '수동 분류'로 떨어진다.
- **방향**

  - 분야 목록은 홈페이지(ConsultPage·_validate)와 로컬(store.py) 어디서든 한 곳 기준으로 맞추고, 계약 테스트로 고정한다(보고서 17번).

### ⑥ 개업 전환 한 번에 점검 · 작업량 S
